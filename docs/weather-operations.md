# Эксплуатация Weather Lab

```sh
npm run db:migrate
npm run weather:check
npm run weather:start
npm run weather:status
npm run weather:verify
```

Команда проверки работает 15 минут без виртуальных исполнений и записей в рабочую базу. Фоновый процесс переживает закрытие терминала и перезапускает дочерний процесс после сбоя. Остановка выполняется командой `npm run weather:stop`. Сборщик BTC использует отдельный процесс.

`npm run weather:launchd` создаёт файл `.collector/lab.polytrader.weather.plist`. Для запуска при входе в систему после остановки обычного фонового процесса используется `launchctl bootstrap gui/$(id -u) "$PWD/.collector/lab.polytrader.weather.plist"`. При работающем фоновом процессе macOS получает запрос `caffeinate -i` на предотвращение сна по бездействию. Закрытие крышки, отключение питания и потеря сети могут прервать сбор. Режим сна проверяется через `pmset -g`. Статус источников и подключения виден в Weather Lab.

Операционный лог находится в `.collector/weather.log`. Секвенсированные сырые сообщения зашифрованным транспортом поступают с публичного WS и локально сохраняются в gzip по часам в `.collector/weather-books/`. Срок хранения 21 день. Для длительных исследований копируйте завершённые файлы `.gz` в выбранное существующее хранилище. Не загружайте сырые котировки в транзакционную базу. Для резервной копии SQL можно использовать Neon restore в пределах текущего окна хранения или выгрузку `pg_dump --schema=weather` с локально защищённой строкой подключения.

При потере соединения старый стакан аннулируется. После перезапуска открытые позиции поднимаются из базы, их рынки продолжают обновляться даже за пределами текущего календарного окна. Незавершённые сигналы не исполняются в новой сессии.

Weather Lab → «Источники» содержит отдельные настройки Telegram для сигналов, исполнений, сбоев и дневного отчёта. Используется общая очередь уведомлений действующего бота. Отчёт охватывает предыдущий календарный день UTC. Для активного эксперимента предупреждение о недоступном стакане ставится в очередь не чаще одного раза за день.

Команда `npm run weather:network -- TOKEN_ID CONDITION_ID [ADDITIONAL_TOKENS...]` проверяет DNS, TCP, сертификат TLS, HTTP 101, снимки, обновления, PING/PONG, переподключение и пару запросов официального REST. Она не размещает сделки и не пишет в рабочую статистику. При ошибке локального DNS сборщик разрешает только фиксированный список доменов Polymarket через DNS over HTTPS Google с коротким кешем. Оригинальный hostname и проверка сертификатов сохраняются. Для диагностики только с системным DNS задайте `WEATHER_DNS_FALLBACK=0`.
