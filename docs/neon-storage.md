# Хранилище PolyTrader Lab

Рабочая ветка определяется по ID `br-young-dew-ba5hjtfp`. При проверке подключения сверяйте ID ветки, последнюю запись `weather.fills` и дату активного эксперимента. Имя ветки и признак default могут измениться после восстановления Neon. Вебхук и планировщик используют существующую функцию `polytrader` на рабочей ветке.

| Данные | Хранение |
| --- | --- |
| Эксперименты, банки, позиции, BUY/SELL/SETTLE, цены и полное доказательство исполнения, история капитала | PostgreSQL, постоянно |
| Сигналы и журнал торговых решений | PostgreSQL. `SKIP` и `SETTLEMENT_HOLD` без связанных открытых позиций архивируются через 14 дней после последнего наблюдения |
| METAR, погодные прогнозы и погодная активность кошельков | PostgreSQL 72 часа после получения, затем сжатый JSONL. Для восстановления Collector перечитывает 30 часов METAR и событий кошельков |
| Операции активных кошельков Copy Trading | Компактные BUY/SELL в PostgreSQL до 24 часов и до 16 МиБ под новые записи, далее сжатый JSONL. Copy Trading берёт сигналы из свежего окна публичного API |
| Технические ошибки | PostgreSQL 14 дней, затем сжатый JSONL. Одинаковые ошибки объединяются за час |
| Сырые снимки и обновления L2 | `.collector/weather-books` на Mac, 21 день. Полные книги, использованные для исполнения, остаются в `weather.fills` |
| Наблюдения размера базы | PostgreSQL 30 дней с шагом 15 минут |

Миграция `014_bound_technical_storage.sql` добавляет защиту от исторической загрузки на уровне PostgreSQL. Для повторяющихся `SKIP` и `SETTLEMENT_HOLD` она хранит первое и последнее время и число записанных наблюдений за час. Существенные изменения цены и вероятности разделяются по интервалам около 3 центов и 3 процентных пунктов, смена источника и версии прогноза также выделяется отдельно. Журнал сохраняет последнюю запись группы. При 90% учтённого лимита приостанавливается запись повторяющихся технических решений и свежей копии активности кошельков. Финансовые записи идут через прежние транзакции. Пороги 70%, 80% и 90% ставят в очередь Telegram не более одного уведомления каждого уровня на пользователя в сутки.

После утверждения миграции применяется только `npm run db:migrate -- 014_bound_technical_storage.sql`. Перед применением сверяйте целевую рабочую ветку. Пока схема ожидает активации, «Погода → Источники» показывает текущее использование и крупнейшие таблицы. История замеров и фоновые уведомления включаются после миграции. Процент показывает размер основной базы. У проекта Neon собственный учёт всех веток, резервных снимков и вычислений.

Сборщик переносит просроченные технические данные в `.collector/archives/retention` небольшими партиями. Он перечитывает gzip, сверяет количество записей и SHA-256 распакованного JSONL, затем сохраняет файл на диск. Удаляются только строки с тем же содержимым, что при экспорте. Ошибка архивирования выводится в «Источниках». Имя файла содержит таблицу и SHA-256. Для восстановления распакуйте нужный файл и загрузите строки в отдельную исследовательскую таблицу или SQLite. Ключ для `weather.inputs` — `(kind,id)`, для `lab.wallet_activity` — `(wallet,id)`, для `weather.audit` и `lab.logs` — `id`. Копируйте завершённые архивы на другой носитель или в закрытое хранилище для защиты от потери Mac.

Архив до очистки содержит 643 527 публичных операций. Локальный файл `.collector/archives/wallet-history-2026-11-14.ndjson.gz` и манифест лежат также в закрытом бакете Neon Object Storage `polytrader-archive`, префикс `wallets/`. Проверка архива сверяет число строк и SHA-256 из манифеста. Для исследования используйте этот файл и не загружайте его в рабочую `lab.wallet_activity`.
